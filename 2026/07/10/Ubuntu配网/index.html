1. 上网流程

1.1. 从两台机器开始

首先我得说一下上网流程。由于我学习的顺序非常混乱，所以我的博客写的顺序也非常混乱，我尽量按“网络为什么会一步步变复杂”的逻辑来厘清。

最简单的网络是什么样的？其实就是两台机器拿一根网线连起来。A 想给 B 发数据，B 想给 A 回数据，只要两边能听懂彼此的数据格式，这件事就结束了。

但是问题马上就来了：如果不是两台机器，而是三台、十台、一百台机器呢？总不能每两台机器之间都拉一根线吧。nnn 台机器两两相连需要大约 n(n−1)2\frac{n(n-1)}{2}2n(n−1)​ 根线，机器一多，线就会变成灾难。

所以人们很自然地想到：能不能把大家都接到一个“中间人”上？

graph TD
    A[主机 A] --- D[交换机 D]
    B[主机 B] --- D
    C[主机 C] --- D

于是就出现了类似上图这样的结构。ABC 三台主机都连接到 D 上，D 负责把数据转发给正确的机器。这个 D 就是交换机。

交换机大致工作在“同一个局域网内部”。你可以先把它理解成一个很聪明的插线板：大家都插在它上面，但它不是把所有数据都广播给所有人，而是会学习每个接口后面连接着谁，然后尽量把数据只转发给目标机器。

那么问题又来了：A 怎么知道自己要找的是 B 呢？在网络里，每台机器需要有一个地址。

1.2. IP 地址：机器在网络里的地址

在 IPv4 情况下，计算机能够拿来使用的地址是一个 32 位二进制数。为了方便人们阅读，它通常被分成 4 个 8 位数字，然后用点隔开，写起来就像这样：最小的是 0.0.0.0，最大的是 255.255.255.255。

比如在一个局域网里，可能有这样的地址：

  • A：192.168.1.2
  • B：192.168.1.3
  • C：192.168.1.4

这样 A 想访问 B 的时候，就可以说：“我要找 192.168.1.3。”交换机再帮它把数据送过去。

不过这里要注意：交换机本身并不是靠 IP 地址来转发以太网帧的，真正底层还会涉及 MAC 地址、ARP 等东西。为了先理解“上网流程”，这里可以先把它粗略理解成：同一个局域网内的机器，只要知道彼此的地址，就可以互相通信。

1.3. DNS：人不想背 IP 地址

现在机器之间终于可以互相访问了，但新的问题又出现了：IP 地址对于人类来说太难记了。

比如你肯定不想每天背一串数字去访问网站。于是人们发明了域名。相比 142.250.xxx.xxx 这种地址，www.google.com、www.baidu.com、www.bilibili.com 显然更适合人类记忆。

但是计算机最终通信时还是要找 IP 地址。也就是说，当你输入一个域名时，系统需要先知道：这个域名对应哪个 IP 地址？

负责回答这个问题的，就是 DNS 服务器。

sequenceDiagram
    participant U as 用户
    participant PC as 电脑
    participant DNS as DNS 服务器
    participant WEB as 目标服务器

    U->>PC: 输入 www.example.com
    PC->>DNS: 查询 www.example.com 的 IP
    DNS-->>PC: 返回 93.184.216.34
    PC->>WEB: 使用 IP 访问目标服务器
    WEB-->>PC: 返回网页数据

DNS 服务器和网络中的其他主机本质上也是一台机器，只不过它经常被别人问：

欸，www.example.com 对应的 IP 地址是多少？

它回答之后，你的电脑再拿着查到的 IP 地址去真正访问目标服务器。

所以一次最简化的访问流程可以理解为：

  1. 用户输入域名，比如 www.example.com。
  2. 电脑先去问 DNS：这个域名的 IP 是多少？
  3. DNS 返回一个 IP 地址。
  4. 电脑再向这个 IP 地址发送数据。

到这里，我们已经有了局域网、交换机、IP 地址和 DNS。看起来一切都挺美好，但如果世界上所有机器都放在同一个大网络里，问题会变得非常恐怖。

1.4. 为什么需要多层网络

如果全世界所有电脑都接在一个巨大的交换机网络里，会发生什么？

首先，规模会非常夸张。交换机需要记住海量设备的位置，广播类流量也可能被放大到不可接受。其次，管理也会非常混乱。学校、公司、家庭、机房不可能全都挤在同一个“平面”里。

还有一个非常现实的问题：IPv4 地址不够用。

IPv4 总共只有 32 位，理论上最多也就大约 2322^{32}232 个地址，也就是 43 亿左右。这个数字看起来很大，但考虑到全球人口、手机、电脑、服务器、摄像头、路由器、各种 IoT 设备，就完全不够用了。

于是网络逐渐变成了分层结构：

  • 家里的设备组成一个家庭局域网。
  • 学校的设备组成校园网。
  • 公司有公司的内网。
  • 这些网络再通过更上层的网络互相连接。

这时就需要一个新的设备：路由器。

1.5. 路由器：连接不同网络的设备

交换机主要负责同一个局域网内部的通信，而路由器负责连接不同的网络。

比如你家里可能有这样一个网络：

  • 手机：192.168.1.10
  • 电脑：192.168.1.11
  • 平板：192.168.1.12
  • 路由器在内网的地址：192.168.1.1

这些设备都在家里的局域网里。它们互相访问时，可以在局域网内部完成。

但如果你的电脑想访问外面的服务器，比如 www.example.com，它会发现：目标 IP 地址不在我这个局域网里。那怎么办？

答案是：把数据交给路由器，让路由器帮我转发出去。

所以路由器通常至少有两个“方向”的接口：

  • 一个接口面向内网，比如家庭局域网，地址可能是 192.168.1.1。
  • 一个接口面向外网，比如运营商网络，地址由运营商分配。

内网设备访问外网时，数据大致会经过这样的路径：

  1. 电脑发现目标不在本地局域网。
  2. 电脑把数据发给默认网关，也就是路由器的内网地址。
  3. 路由器收到数据后，根据自己的路由表决定往哪里转发。
  4. 数据经过更多路由器，一跳一跳到达目标服务器。
  5. 目标服务器返回数据，数据再沿着网络回到你的路由器。
  6. 路由器再把数据交还给内网里的电脑。

这里的“默认网关”非常重要。

1.6. 网段和子网掩码：怎么判断对方是不是“自己人”

电脑怎么知道一个目标 IP 是不是在同一个局域网里？这就需要子网掩码。

  • IP 地址：192.168.1.23
  • 子网掩码：255.255.255.0

如果电脑要访问 8.8.8.8，它一算，发现这个地址不在 192.168.1.0/24 里，那就认为这是“外面的人”，需要交给网关。

1.8. NAT：很多内网设备共用一个外网地址

这里还有一个常见现象：家里那么多设备，为什么它们都能上网？难道每个设备都有一个公网 IPv4 地址吗？

通常不是。

家庭、公司、学校内部经常使用一些私有地址，比如：

  • 192.168.0.0/16
  • 172.16.0.0/12
  • 10.0.0.0/8

这些地址可以在内网里随便规划，但不能直接拿到公网互联网上当全球唯一地址使用。比如你家可以有一台 192.168.1.23，别人家也可以有一台 192.168.1.23，因为它们都只在各自的内网里有意义。

那内网设备怎么访问公网呢？这通常会用到 NAT，也就是网络地址转换。

简单说，内网电脑访问外网时，路由器会把数据包里的源地址从内网地址改成自己的外网地址，并记录这个连接是谁发起的。外面的服务器把响应发回路由器后，路由器再根据记录把数据转回内网里的那台电脑。

sequenceDiagram
    participant PC as 内网电脑 192.168.1.23
    participant R as 路由器/NAT 203.0.113.5
    participant S as 外网服务器

    PC->>R: 源地址 192.168.1.23，访问外网服务器
    R->>S: 改成源地址 203.0.113.5，再发出去
    S-->>R: 响应 203.0.113.5
    R-->>PC: 查记录，转回 192.168.1.23

所以从外部服务器的视角看，它可能只看到你家路由器的外网地址；但从你家内部看，其实是电脑、手机、平板等很多设备在共用这个出口。

这就是为什么 IPv4 不够用之后，NAT 变得非常常见。它让大量内网设备可以共享较少的公网 IPv4 地址。当然，NAT 不只是为了解决地址不够用，它也带来了内外网隔离等效果，但最直观的理解可以先从“多个内网设备共用一个外网出口”开始。

1.9. DHCP：这些地址都是从哪来的

现在我们已经提到了很多配置：

  • IP 地址
  • 子网掩码
  • 默认网关
  • DNS 服务器

那这些东西到底是从哪来的？难道每次联网都要手动填吗？

当然可以手动填，这叫静态配置。但大多数时候，我们接上网线或者连上 Wi-Fi 后，系统会自动获得这些配置。负责这件事的协议叫 DHCP。

DHCP 可以理解成局域网里的“自动分配员”。当你的电脑刚接入网络时，它还不知道自己该用什么 IP，于是会在局域网里问：

有没有 DHCP 服务器？我需要一个地址。

sequenceDiagram
    participant PC as 新接入的电脑
    participant DHCP as DHCP 服务器/路由器

    PC->>DHCP: DHCP Discover：有没有人能分配地址？
    DHCP-->>PC: DHCP Offer：可以给你 192.168.1.23
    PC->>DHCP: DHCP Request：那我就要这个地址
    DHCP-->>PC: DHCP ACK：确认，同时给你网关和 DNS

在家庭网络里，这个 DHCP 服务器通常也在路由器上。所以家用路由器经常同时承担很多角色：

  • 作为交换机或无线 AP，让内网设备互相连接。
  • 作为路由器，连接内网和外网。
  • 作为默认网关，帮内网设备转发外部流量。
  • 作为 DHCP 服务器，自动分配 IP、网关、DNS 等配置。
  • 作为 DNS 转发器，帮内网设备转发 DNS 查询。
  • 作为 NAT 设备，让多个内网设备共用一个外网地址。

这也是为什么我们平时说的“路由器”其实经常不是一个纯粹的路由器，而是一个把交换、无线接入、路由、DHCP、NAT、DNS 转发等功能打包在一起的小盒子。

1.10. 小结：从简单到复杂

所以我们可以把上网流程按理解顺序串起来：

  1. 最开始，两台机器可以直接连线通信。
  2. 机器多了以后，两两连线太混乱，于是出现交换机，把多台机器组织成局域网。
  3. 每台机器需要地址，于是使用 IP 地址标识网络中的设备。
  4. 人不想记 IP 地址，于是出现域名和 DNS，用域名查询 IP。
  5. 网络规模继续扩大，不同局域网之间需要互联，于是出现路由器。
  6. 电脑用子网掩码判断目标是不是在同一个网段。
  7. 如果目标不在本地网段，就把数据交给默认网关。
  8. IPv4 地址不够用，大量内网使用私有地址，并通过 NAT 共用外网出口。
  9. 手动配置 IP、掩码、网关、DNS 太麻烦，于是 DHCP 负责自动分配这些信息。

这样再回头看“上网”这件事，它大概就是：先确定自己是谁，再判断目标在哪里；如果目标在本地，就本地找；如果目标在外面，就交给网关；如果目标写的是域名，就先问 DNS；如果自己的地址配置都不知道，就先找 DHCP 要一份。

2. 工具介绍

在真正配置网络之前，我觉得最需要先弄清楚的不是某个命令怎么写，而是：这些工具分别站在哪一层，它们之间是什么关系。

Linux 网络配置最容易把人绕晕的地方，就是工具名字太多了。Netplan、systemd-networkd、NetworkManager、ifupdown、wpa_supplicant、dhclient 全都可能出现。它们看起来都和“联网”有关，但并不是同一类东西。

如果把层级关系先捋清楚，后面就不容易乱配。

Netplan 不是和 systemd-networkd、NetworkManager 并列抢网卡的东西。它更像是一个上层配置入口，用来生成后端配置。

真正长期管理网卡的，通常是下面这些后端之一：

  • systemd-networkd
  • NetworkManager
  • ifupdown

它们容易互相冲突。一般来说，一张网卡最好只交给其中一个工具管理。

2.1. Netplan

Netplan 是 Ubuntu 里很常见的网络配置入口。

它本身通常不是那个一直在后台守着网卡的人。你写好 Netplan 配置以后，它会把配置翻译成后端真正能用的文件，然后交给 systemd-networkd 或 NetworkManager。

2.2. systemd-networkd

systemd-networkd 是一个网络管理后端。

它适合服务器这种网络环境比较固定的机器。比如一台旧电脑放在桌子底下当服务器，插着固定网线，不需要天天切 Wi-Fi，这种场景就很适合。

如果选择它，就尽量让它统一管理目标网卡。不要又让 NetworkManager 管同一张网卡，也不要手动长期跑一个 dhclient 来抢 DHCP。

2.3. NetworkManager

NetworkManager 也是一个网络管理后端。

它在桌面 Linux 上很常见，因为桌面电脑经常需要切换 Wi-Fi、热点、VPN、有线网络。图形界面里的网络设置很多时候就是它在背后工作。

如果是一台经常移动、经常换 Wi-Fi 的电脑，用它很正常。但如果是一台服务器，尤其是只想固定走有线网卡的服务器，用 systemd-networkd 通常会更清爽。

重点不是谁绝对更好，而是：

不要让 NetworkManager 和 systemd-networkd 同时管理同一张网卡。

2.4. ifupdown

ifupdown 是比较老的网络配置方式，Debian 系里以前很常见。

它通常通过类似 /etc/network/interfaces 的文件配置网络。现在新版本 Ubuntu Server 更常见的是 Netplan + systemd-networkd。

如果你在网上搜教程，很可能会搜到很多 ifup、ifdown、/etc/network/interfaces 相关内容。它们不一定错，但不一定适合你当前这台 Ubuntu 机器。

如果你的系统已经在用 Netplan，就不要随手再把 ifupdown 的配置混进去。

2.5. wpa_supplicant

wpa_supplicant 和前面几个不太一样。

它主要负责认证，比如：

  • Wi-Fi 密码认证。
  • 校园网有线 802.1X 认证。

它不是用来给你分配 IP、网关、DNS 的。它更像是在说：

先证明你有资格接入这个网络。

认证通过以后，后面通常还要靠 DHCP 获取 IP、网关和 DNS。

在我的校园网场景里，wpa_supplicant 负责有线 802.1X 认证，而 systemd-networkd 负责后续 DHCP 和路由配置。Netplan 则负责把这两边的配置生成出来。

2.6. dhclient

dhclient 是 DHCP 客户端，用来向 DHCP 服务器申请 IP、网关、DNS。

它本身不是一个完整的网络管理体系。你可以手动运行它让某张网卡获取地址，但如果系统已经由 systemd-networkd 或 NetworkManager 管理 DHCP，就不要再额外手动跑一个 dhclient 抢同一张网卡。
